# 근거 기반 숙련도

| Level | 의미 | 검증 가능한 근거 종류 |
| --- | --- | --- |
| 0 | 미학습/이해 미확인 | 근거 없음. 설명을 읽기만 했다면 여기에 유지 |
| 1 | 개념 이해 | `learner_explanation`: 학습자가 정의와 목적을 자신의 말로 설명 |
| 2 | 코드 해석 | `code_reading`: 실제 코드의 동작과 개념을 연결한 설명 |
| 3 | 설계 판단 | `design_decision`: 요구사항 아래 대안의 장단점과 선택 이유 |
| 4 | 응용 및 검증 | `application_validation`: 실제 적용·검증 결과와 문제 해결 |

Level 1의 '기본 의미 이해'도 강의 제공 사실만으로 확인하지 않습니다. 높은 수준의 근거가 낮은 수준의 이해를 포함할 수 있어 모든 단계의 별도 퀴즈를 요구하지 않습니다. `verified_level` 이상의 수준을 입증하는 근거 하나 이상이 필요합니다. 근거의 수준은 위 종류와 일치해야 합니다. 적용 근거는 실제 project/case와 연결합니다. 검사기는 형식만 확인하며 설명의 진실성과 수준의 적절성은 사람이 판단합니다.

`estimated_level`은 독립된 가설이며 null 또는 0~4입니다. 검증 수준보다 낮을 수도 있습니다(재점검 필요 신호). 강의·대화로 추정이 생겨도 verified를 올리지 않습니다. `learning_notes`에는 배운 내용, `unverified_notes`에는 미확인, `needs_learning`에는 보충 과제, `case_ids`에는 실제 적용 연결을 기록합니다. 자세한 필드는 [데이터 계약](../docs/data-contract.md)을 따릅니다.

근거는 날짜·수준·종류·구체적 요약·저장소 내 공개 가능한 source 문서를 갖습니다. source에는 학습자의 실제 설명/판단 또는 실행 결과가 있어야 합니다. 대화 원문·개인정보를 무단 저장하지 않습니다. 여러 제품의 근거를 누적하고 Git으로 이력을 남깁니다. 근거가 부족하거나 상충하면 수준을 보수적으로 유지/수정하고 재점검 이유를 기록합니다.
